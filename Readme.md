# 🎓 **Youth Tracking Platform**



A robust, enterprise-grade behavioral health monitoring platform designed to ingest student telemetry, perform predictive risk analysis using LLMs, and facilitate secure counselor interventions. The system prioritizes data privacy, identity confidentiality, and role-based operational segregation.





## 🚀 **Platform Overview**



This platform bridges the gap between raw behavioral telemetry and actionable clinical intervention. It transforms disparate data points (absences, academic performance, appointment history) into a normalized risk score, allowing teams to monitor student wellbeing while strictly adhering to confidentiality standards.



#### Core Architecture:

* Normalized Telemetry: Data is ingested via standardized CSV imports and API endpoints, normalizing metrics into a cohesive risk model.



* Identity Confidentiality: The system uses an Anonymous ID architecture. Clinical staff operate on anonymized profiles; sensitive PII is isolated, ensuring behavioral tracking is decoupled from raw identity data.

## 

## 🏗️ **Technical Architecture**



The platform follows a Decoupled RESTful Architecture, utilizing Django REST Framework (DRF) to expose normalized data endpoints which are consumed by the React frontend.



* Client-Server Separation: The backend acts as a high-security "headless" data provider, decoupling database and clinical logic from the user interface.



* Service-Oriented Design: By exposing standardized API links (endpoints), the platform is natively scalable. The same backend can support future mobile applications (iOS/Android) or third-party integrations without requiring changes to the core business logic.



* Security Filter Layer: A centralized "Track B Security Filter" resides within the API layer, ensuring that data redaction and role-based permissions are enforced consistently, regardless of the client connecting to the system.



## 👥 **Role-Based Functionality**



|**Role**|**Responsibility**|

## 🔒 **Security \\\& Authentication**



Security is built into the transport and logic layers:



* JWT (JSON Web Tokens): Used for stateless authentication. Upon login, tokens are issued to manage sessions securely across the React frontend and Django backend.



* OTP (One-Time Password): Integrated for high-security actions and multi-factor authentication (MFA) requirements, ensuring that sensitive data access remains verifiable.



* Permission Logic: A granular "Track B Security Filter" sits within the API layer. It dynamically redacts sensitive qualitative fields (like raw intake notes) based on the user's role and group membership.





## 🧠 **Technology Stack**



* Backend: Django \\\& Django REST Framework (Robust API handling, ORM, and secure data modeling).



* Frontend: React (State management, secure dashboard routing).



* AI/Analysis: LLM integration with llama3 model for deterministic behavioral analysis, evaluating risks based on longitudinal telemetry.



* Data/Storage: SQLITE (Secure relational data), Pandas (CSV normalization and telemetry processing)





## 📊 **Data Management**



* CSV Ingestion: The platform supports normalized CSV uploads. The system validates the schema (anonymous\\\_id, isolation\\\_indicator\\\_score, etc.) to prevent malformed data injection.



* Data Redaction: The API employs a "counselor-only" visibility mask. Operators can input data, but they cannot read the specific clinical diagnostic content generated by counselors or the LLM analysis.



* Deterministic Mode: AI analyses are generated in a deterministic mode to ensure consistency in risk evaluation, minimizing hallucinations and ensuring the counselor receives reliable, repeatable insights.





## 🧪 **Automated Testing \& Quality Assurance**



To ensure system reliability and security, we employ a comprehensive automated testing strategy using the following tools.



#### Tools \& Frameworks:

* Pytest: The primary framework for test discovery and execution, providing an efficient environment for unit and integration testing.



* Pytest-Django: Simplifies database integration, allowing tests to run against an isolated, temporary database instance.



* APIClient (DRF): Used to simulate authenticated HTTP requests, enabling the verification of endpoints without the overhead of a full browser simulation.



#### Test Coverage:

Our test suite ensures that the core features of the platform remain stable:



1. Bulk Upload Validation: Tests verify that the system correctly parses CSV files, enforces schema validation, and handles data integrity (e.g., preventing duplicate IDs).

2. Authentication \& Permissions: Tests ensure that unauthorized users are denied access and that only authenticated users can access sensitive telemetry.

3. Security Filters: Validates that the Security correctly redacts sensitive fields based on user roles.

## 🛡️ **Security Policy**



This platform is designed to be HIPAA/GDPR compliant in its data handling philosophy. By separating the Beneficiary identification from the CaseFile telemetry, the system ensures that if a behavioral data breach were to occur, the data remains dissociated from the student's real-world identity.
